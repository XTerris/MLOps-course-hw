# ДЗ 1 — Окружение, первый инференс Qwen3, бенчмарк машины

Рабочее окружение, общий код инференса и бенчмарк с отдельными замерами
загрузки, скорости генерации и пиковой RSS. Результаты запусков и разбор
исправлений — в [отчёте](docs/hardware.md).

## Запуск

```bash
uv sync --locked  # Python 3.12; версии пакетов берутся из uv.lock
make generate     # генерация
make bench        # один прогрев, три замера; результат в docs/bench.json
make test         # unit-тесты без загрузки весов
make check        # полная самопроверка, в том числе на другой модели
```

`uv` должен быть установлен и доступен в `PATH`. Проект уже инициализирован,
поэтому повторять `uv init` не нужно. `make install` выполняет ту же установку
зависимостей, что и `uv sync --locked`.

Первый запуск скачивает веса и токенизатор из Hugging Face в пользовательский
кэш. Полная проверка дополнительно скачивает маленькую альтернативную модель.
Веса, кэш и `.venv` в Git не входят. После скачивания можно измерять без сети:

```bash
HF_HUB_OFFLINE=1 make generate
HF_HUB_OFFLINE=1 make bench
HF_HUB_OFFLINE=1 make check
```

## Конфигурация и результаты

Имя модели читается только из `params.yaml`. Там же задаются устройство
(`auto`, `cpu`, `cuda` или `mps`), dtype, seed, параметры генерации и бенчмарка.
Текущие настройки соответствуют Mac Apple Silicon: MPS, bfloat16 и модель
размера 1.7B по таблице первой лекции. На другом железе нужно изменить конфиг,
а не Python-код.

При `temperature: 0.0` используется жадный поиск. Вывод содержит только ответ,
не более 200 новых токенов; модель может завершить его раньше по EOS.
Бенчмарк считает фактическое число токенов, включая EOS, если он был выдан.

`docs/bench.json` — перезаписываемый результат последнего `make bench`.
Зафиксированные результаты для отчёта хранятся отдельно в `docs/results/`.
RSS указана в МиБ, несмотря на сохранённое имя поля `peak_rss_mb`.

`data/` и `conf/` пока содержат только `.gitkeep`: данные для первого инференса
не нужны, а параметры намеренно не дублируются во втором конфиге.
