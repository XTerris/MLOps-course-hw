# ДЗ 3 — GitHub Issues: датасет, DVC и честный split

Подготовлен собственный англоязычный chat-датасет для классификации GitHub
Issues Python-проектов по четырём типам: `bug`, `documentation`, `feature`,
`question`. Исходные labels используются как слабая разметка; неоднозначные
issues, pull requests, пустые и неанглийские тексты исключаются. Обучение модели
в этой работе не выполняется.

| Результат | v1 | v2 |
|---|---:|---:|
| До очистки | 1 800 | 2 800 |
| После очистки | 1 767 | 2 747 |
| Репозитории | 100 | 145 |
| Train / validation / test | 1 406 / 182 / 179 | 2 188 / 282 / 277 |
| Классы | 4 | 4 |
| Пересечения train/test | 0 | 0 |

Версии фиксируются Git-тегами `hw3-data-v1` и `hw3-data-v2`, а содержимое
пяти JSONL хранится в DVC. Git содержит код, параметры, `dvc.lock`, метрики и
отчёты, но не сами данные.

## Что находится в отчёте

- [Паспорт датасета](docs/datasheet.md) — источник, лицензии, схема, фильтры,
  состав, смещения и ограничения;
- [Разбор пяти дефектов](docs/defects.md) — проявление, первопричина,
  исправление и фактическое подтверждение каждого дефекта;
- [Проверка результата](docs/validation.md) — тесты, воспроизводимость, DVC и
  соответствие критериям задания;
- [Разница метрик v1/v2](docs/results/v1-v2-metrics.diff) — сохранённый вывод
  `dvc metrics diff hw3-data-v1 hw3-data-v2`;
- [Описание источника](sources/SOURCE.md) — правила получения данных через
  GitHub REST API.

## Пайплайн

```text
GitHub REST API
      │
      ▼
 collect ──► clean ──► diversity ──► split
 raw.jsonl   clean.jsonl    │          ├─ train.jsonl
                            │          ├─ val.jsonl
                            │          └─ test.jsonl
                            └─ hard quality gate
```

- `collect` собирает детерминированную сбалансированную выборку, ограничивая
  вклад одного репозитория 30 примерами;
- `clean` валидирует JSONL, маскирует ПДн и удаляет exact/near duplicates;
- `diversity` останавливает пайплайн при нарушении порогов размера,
  разнообразия, числа групп или баланса классов;
- `split` распределяет репозитории целиком в пропорции около 80/10/10 и
  проверяет отсутствие контаминации.

Параметры находятся в `params.yaml`, граф и артефакты — в `dvc.yaml`,
фактические значения — в `metrics/*.json`.

## Быстрый запуск

Из папки `HW 3`:

```bash
make install
make test
make repro
make check
```

Для нового сбора рекомендуется передать публичный GitHub token только через
окружение:

```bash
GITHUB_TOKEN=... make v2
```

Токен не записывается в параметры, метрики или логи. Без токена сборщик
учитывает анонимный rate limit, `Retry-After` и `X-RateLimit-Reset`.

## Команды

| Команда | Назначение |
|---|---|
| `make repro` | Воспроизвести актуальный DVC-граф |
| `make test` | Запустить 10 offline unit-тестов |
| `make check` | Unit-тесты и 8 приёмочных проверок |
| `make v1` | Переключить параметры и собрать v1 |
| `make v2` | Переключить параметры и собрать v2 |
| `make diversity` | Повторить diversity gate |
| `make contamination` | Проверить train/test отдельно |
| `make dag` | Показать DVC-граф |

Данные выбранной версии восстанавливаются из локального default remote:

```bash
uv run dvc pull
```

Видео и публикация репозитория в текущий этап не входят.
