## Назначение и состав

Датасет предназначен для supervised fine-tuning модели, которая маршрутизирует
англоязычные GitHub Issues в один из четырёх классов: `bug`, `documentation`,
`feature`, `question`. Формат каждой строки — chat JSONL с полями `id`, `topic`
и тремя сообщениями `system → user → assistant`. `topic` содержит полное имя
репозитория и используется как ключ группового split.

| Версия | Raw | Clean | Репозитории | Train | Val | Test |
|---|---:|---:|---:|---:|---:|---:|
| v1 | 1800 | 1767 | 100 | 1406 | 182 | 179 |
| v2 | 2800 | 2747 | 145 | 2188 | 282 | 277 |

Распределение классов после очистки:

|---|---:|---:|---:|---:|

| v2 | 677 | 694 | 692 | 684 |

## Источник и лицензирование

Источник — публичный GitHub REST API, issues Python-репозиториев за период
2024-01-01…2025-12-31. Разметка строится из стандартных labels: `bug`,
`documentation`/`docs`, `enhancement`/`feature`/`feature request`, `question`.
Issue с labels из нескольких целевых классов отбрасывается.

В пул допускаются только репозитории, для которых GitHub определил SPDX-лицензию
MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause или ISC. GitHub Terms указывают, что
вклад в репозиторий с лицензией предоставляется на условиях этой лицензии:
<https://docs.github.com/en/site-policy/github-terms/github-terms-of-service>.
`id` вида `github:owner/repo#number` сохраняет происхождение и позволяет найти
оригинал. Набор предназначен для учебного некоммерческого использования.

Подробное описание происхождения и повторного сбора находится в
[`sources/SOURCE.md`](../sources/SOURCE.md).

Распределение лицензий v2: Apache-2.0 — 896, MIT — 717, BSD-3-Clause — 614,
BSD-2-Clause — 384, ISC — 189.

## Сбор и переработка

Сборщик использует фиксированные диапазон дат, API version и порядок запросов.
Токен читается только из `GITHUB_TOKEN`; без токена учитываются `Retry-After` и
`X-RateLimit-Reset`. Из исходника удаляются pull requests, пустые title/body,
неанглийские записи (langdetect, вероятность ≥ 0,85), неоднозначные labels и
репозитории вне разрешённого списка лицензий. На один репозиторий допускается
не более 30 строк. В v2 фактически просмотрено 24 588 issues; отброшено 835
неоднозначных, 187 пустых, 946 неанглийских и 19 820 сверх лимита репозитория.

Пять вариантов system prompt выбираются детерминированно по SHA-256 от `id`.
Классы до очистки идеально сбалансированы: по 450 в v1 и по 700 в v2.

## Очистка и качество

Порядок clean: строгая схема → фильтр длины → маскирование ПДн → точная
дедупликация → near-duplicate MinHash/LSH с точной проверкой Жаккара. Порог
near-dup равен 0,85 и совпадает с порогом проверки контаминации.

Для v2 удалено 43 строки по длине и 10 near-dup; буквальных дублей не найдено.
В 13 строках замаскировано 24 email-адреса. Длины user-сообщений v2: p50=807,
p90=3428, p99=8724, максимум=11928 символов. После очистки классы составляют:
bug — 677, documentation — 694, feature — 692, question — 684; крупнейший
класс занимает 25,26%.

Повторяемость assistant-ответов 99,85% ожидаема для четырёхклассовой задачи и
не является признаком шаблонной генерации. Поэтому этот порог равен 1,0, а
разнообразие дополнительно контролируется числом классов, их балансом, числом
репозиториев, долей крупнейшего репозитория и пятью system prompts. v2 проходит
гейт: 2747 примеров, 145 групп, крупнейшая группа 1,09%, p90/p10 длины ответа
4,33, нарушений порогов нет.

## Split и контаминация

Репозитории целиком распределяются между train/val/test детерминированным
жадным алгоритмом с seed 42 и целями 80/10/10. Фактические доли v2:
79,65% / 10,27% / 10,08%. В train/val/test находятся 120/13/12 непересекающихся
репозиториев. Отдельный гейт подтверждает ноль пересечений train/test по `id`,
нормализованному тексту, репозиторию и near-dup парам.

| Версия | Train | Validation | Test | Группы train/val/test |
|---|---:|---:|---:|---:|
| v1 | 1 406 | 182 | 179 | 84 / 8 / 8 |
| v2 | 2 188 | 282 | 277 | 120 / 13 / 12 |

## Ограничения и риски

- Labels назначены авторами разных проектов и могут означать немного разные
  процессы; это слабая, а не экспертная разметка.
- Выборка ограничена популярными лицензированными Python-репозиториями и двумя
  календарными годами; она не представляет весь GitHub.
- В body остаются Markdown, шаблоны issues, логи и фрагменты кода. Это полезный
  сигнал задачи, но модель может выучить шаблоны отдельных проектов.
- Регулярные выражения ПДн покрывают телефон, email и дату рождения около явного
  маркера, но не гарантируют обнаружение всех персональных данных.
- Исходные issues могут быть изменены или удалены после сбора. Воспроизводимость
  конкретных v1/v2 обеспечивается DVC-кэшем и локальным remote.
