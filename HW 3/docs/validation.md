# Проверка результата

Документ фиксирует, чем подтверждена готовность ДЗ 3. Основной сценарий проверки
из папки `HW 3`:

```bash
make install
make check
```

## Критерии приёмки

| Критерий | v1 | v2 | Результат |
|---|---:|---:|---|
| строк после очистки, не менее 1 000 | 1 767 | 2 747 | пройдено |
| классов, ровно 4 | 4 | 4 | пройдено |
| репозиториев, не менее 50 | 100 | 145 | пройдено |
| доля крупнейшего класса, не более 35% | 25,30% | 25,26% | пройдено |
| доля крупнейшего репозитория, не более 10% | 1,70% | 1,09% | пройдено |
| system prompts, не менее 3 | 5 | 5 | пройдено |
| пересечения train/test по ID | 0 | 0 | пройдено |
| пересечения train/test по тексту | 0 | 0 | пройдено |
| пересечения train/test по группе | 0 | 0 | пройдено |
| near-duplicate пары train/test | 0 | 0 | пройдено |

## Offline-тесты

`tests/test_hw3.py` содержит 10 тестов без сетевых запросов:

1. повтор API-запроса после rate limit и чтение `Retry-After`;
2. отображение GitHub labels в четыре канонических класса;
3. языковой фильтр;
4. строгая схема и номер строки в ошибке JSONL;
5. маскирование email, телефона и даты рождения;
6. exact duplicate;
7. near duplicate;
8. детерминированный групповой split;
9. поиск ID-, text-, group- и near-dup-контаминации;
10. положительный и отрицательный сценарии diversity gate.

## Восемь приёмочных проверок

`tests/check.sh` отдельно проверяет:

1. данные исключены из Git, все пять JSONL объявлены DVC-артефактами, remote
   настроен;
2. clean удаляет exact и near duplicates и маскирует три вида ПДн;
3. битая третья строка JSONL останавливает стадию и упоминается в ошибке;
4. переключение v1/v2 меняет результат стадии collect;
5. контаминация train/test равна нулю;
6. вырожденный набор отклоняется diversity gate с объяснением причин;
7. реальный датасет проходит diversity gate;
8. в Git нет мусора и файлов тяжелее 5 МБ.

## Воспроизводимость и версии

Пять файлов данных — `raw`, `clean`, `train`, `val`, `test` — перечислены в
`dvc.yaml` и загружены в локальный DVC remote. Четыре JSON-файла метрик имеют
`cache: false`, поэтому доступны Git и команде `dvc metrics diff`.

Теги `hw3-data-v1` и `hw3-data-v2` фиксируют код, параметры, lock-файл и
метрики каждой версии. Для проверки одной версии достаточно переключиться на
тег и выполнить `uv run dvc pull`; повторный сетевой сбор для этого не нужен.

## Негативные сценарии

- недобор хотя бы одного класса завершает `collect` ошибкой и записывает
  `complete=false` вместе с причинами отбраковки;
- невалидная JSONL-строка завершает `clean` ошибкой с путём и номером строки;
- нарушение любого diversity-порога завершает стадию ненулевым кодом;
- найденная контаминация завершает `split` и отдельную проверку ненулевым кодом.

## Итог

Обе версии удовлетворяют количественным ограничениям, разделены по
репозиториям и не имеют обнаруженной контаминации между train и test. Данные
отделены от Git и восстанавливаются через DVC. Последовательный запуск локальных
`make check` в `HW 1`, `HW 2` и `HW 3` подтверждает отсутствие регрессий.
