# Разбор дефектов стадии tokenize

Работа выполнена на версии v2 собственного датасета GitHub Issues из ДЗ 3:
2188 примеров train и 282 примера validation. Все приведённые ниже числа
получены токенизатором `Qwen/Qwen3-0.6B` при `enable_thinking: false` и
`max_seq_len: 1792`. Проверяющий скрипт не изменялся; его отпечаток —
`f2002c8c9519`.

## 1. Промпт ошибочно участвовал в лоссе

В исходном `mask_prompt` возвращалась копия `input_ids`, поэтому ни одна
позиция промпта не получала `-100`. Модель обучалась воспроизводить системную
инструкцию и текст issue вместо классификации. Формально такой прогон мог
показывать низкий loss, потому что длинный и шаблонный промпт предсказывать
легче короткого ответа.

Исправление маскирует первые `n_prompt` токенов значением `-100`; в лоссе
остаются только ответ assistant и завершающий EOS. После исправления в train
под наблюдением находятся 6341 из 772903 токенов, то есть 0,82%, а в
validation — 804 из 106339, или 0,76%. Маленькая доля ожидаема: ответ задачи
классификации состоит из одной метки и EOS. Проверка декодировала позиции
`label != -100` и сопоставила их с исходным ответом на всех 2114 сохранённых
train-примерах.

## 2. Обучение и инференс использовали разные chat template

Train-путь собирал реплики вручную через строку со спецтокенами Qwen3, тогда
как inference-путь вызывал `apply_chat_template`. Ручная строка не учитывала
логику шаблона модели, в частности пустой блок рассуждений при
`enable_thinking: false`. Поэтому модель обучалась на формате, отличном от
того, который получила бы при генерации.

Ручной шаблон и строковые спецтокены удалены. Оба пути теперь проходят через
единственную функцию `build_chat_text` в `src/prompt.py` и один вызов
`apply_chat_template`; различается только `add_generation_prompt`. Для всех
282 validation-диалогов проверено побайтовое условие: inference-строка является
префиксом train-строки. В остальных файлах `src/` найдено 0 вызовов
`apply_chat_template` и 0 вручную записанных токенов ролей.

## 3. Коллатор добавлял padding справа

У `DynamicPaddingCollator` значением по умолчанию было `padding_side="right"`,
а настройка из `params.yaml` не передавалась токенизатору. При генерации
decoder-only модель продолжает последний токен последовательности, поэтому в
батче разной длины короткая строка продолжала pad-токены. На batch size 1
дефект был незаметен.

Токенизатор и сохранённые артефакты теперь получают `padding_side: left`, а
коллатор использует левую сторону по умолчанию. `attention_mask` на padding
равна 0, `labels` равны `-100`, ширина выбирается динамически по самому
длинному примеру батча. В контрольном батче с длинами 89 и 107 получилась
ширина 107 и 18 pad-позиций слева; ошибочных pad-позиций с label, отличным от
`-100`, — 0. У короткой строки края attention mask равны 0 и 1 соответственно.

## 4. Обрезка не измерялась и была слишком большой

Исходная `truncation_stats` возвращала пустой словарь, поэтому отчёт не
показывал потерю хвоста ответа. При выданном `max_seq_len: 232` фактически
обрезались 1142 из 2188 train-примеров (52,2%) и 157 из 282 validation-примеров
(55,7%). У 1132 и 155 примеров соответственно ответ исчезал целиком, и такие
записи приходилось выбрасывать.

Стадия теперь считает число и долю обрезанных до фильтрации, сравнивает их с
порогом 5% и сохраняет значения в метрики. На собственном датасете p95 длины
равен 1509 токенам для train и 1779 для validation. Выбран
`max_seq_len: 1792` — минимальное значение, кратное 128 и проходящее порог на
обоих сплитах. После повторного прогона обрезано 75 train-примеров (3,43%) и
14 validation-примеров (4,96%); полностью без supervision осталось 74 и 14.
Полные хвосты отражены отдельно: p99 равен 2707/2606, максимум — 8686/5391.

## Дополнительная статистика

Граница промпта совпала по токенам во всех примерах датасета, поэтому BPE
fallback сработал 0 раз. Искусственная проверка со склейкой на слове
«Привет» активировала запасной путь и поставила границу на токене 3. Packing
сохраняет `seq_lens`: для train число последовательностей уменьшается с 2114
до 433, а оценка шагов при batch size 8 — с 265 до 55. Эти бины нельзя
передавать в обучение без блочно-диагональной attention mask.
