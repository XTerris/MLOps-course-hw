# ДЗ 5 — LoRA для классификации GitHub Issues

## Вход и эксперимент

Используются собственные `../HW 4/data/tokenized/train.pt` и `val.pt`:
2114 train и 268 validation-примеров версии v2 GitHub Issues из ДЗ 3.
Это обычные последовательности с маской ответа, без packing. Данные не
токенизируются заново и не копируются; зависимости DVC связывают работы.

Модель — `Qwen/Qwen3-0.6B`, ревизия зафиксирована в `params.yaml`.
LoRA: r=8, alpha=16, dropout=0.05, семь проекций внимания и MLP.
Первый вариант обучает адаптеры слоёв 0–27; второй — только 14–27.
Базовые веса, embedding и lm_head заморожены. Полный прогон — одна эпоха,
265 обновлений при эффективном батче 8. Val считается на всех 268 примерах
до обучения, каждые 10 шагов и на шаге 265.

В отличие от обычного вычисления полных логитов, `src/loss.py` оставляет
только хвост от первого токена ответа. Loss и градиенты совпадают с
полным masked causal LM loss; эквивалентность проверяется тестом. Поэтому
при длинных issue можно оценивать батчами по 8 без матрицы логитов на весь
промпт. Метрики памяти — выборочный максимум MPS driver allocations.

## Запуск

Окружение общее с ДЗ 1–4: `pyproject.toml`, `uv.lock` и `.venv` находятся
в корне MLOps. Отдельного окружения ДЗ 5 нет. Из папки `HW 5`:

```bash
make install      # общее окружение, uv sync --project .. --locked
make test         # шесть тестов математики и цикла обучения
make repro        # DVC: оба варианта -> plot и compare
make check        # исходные девять проверок
```

Для запуска без DVC: `make train`, затем `make compare` и `make check`.
Короткий диагностический прогон сохраняется отдельно:

```bash
uv run --project .. --locked python -m src.train \
  --variant all_layers --max-steps 5 --val-limit 8 --out /tmp/hw5-smoke
```

`train.max_steps: null` означает полную эпоху. Smoke-результаты не заменяют
полные адаптеры. После изменения кода, конфигурации, lock-файла или входных
тензоров нужно повторить обучение: checker проверяет отпечаток входов.

## Место на диске и память

- `make clean` удаляет адаптеры, метрики и графики — всё пересоздаётся
  `uv run --project .. --locked dvc repro --force` или `make train`.
  Общее окружение сохраняется.
- `make check` работает во временной папке и сам её удаляет, в том числе
  брошенные прошлыми прерванными запусками.
- Если машина уходит в своп: `train.batch_size: 1` и `grad_accum: 8` —
  эффективный батч тот же. Gradient checkpointing в конфиге уже включён.

## Подсказки

- Смена железа — правка `model.device` и `model.dtype` в `params.yaml`, не кода.
  На CPU ставьте `float32` и `max_steps` для пробных прогонов.
- Проверка 4 копирует папку адаптера во временный каталог и поднимает его
  без сети — ровно как у человека, которому вы его отдали.
- Проверка 5 дважды обучает по три шага. Если кривые разные, ищите, откуда
  берётся случайность.

## Передача адаптера и хранение результатов

В `models/adapter_<variant>/` сохранены `adapter_model.safetensors`,
`adapter_config.json`, токенизатор, шаблон чата и `inference_config.json`
с моделью и настройками генерации. Базовые веса нужно иметь в HF-кеше
отдельно. Compare читает токенизатор из папки адаптера, генерирует жадно
и показывает все пять вопросов с исходными labels GitHub.

В Git входят код, параметры, DVC lock, отчёты, график и сравнение.
Адаптеры и JSON-метрики кешируются DVC, тензоры восстанавливаются стадией
HW 4. Они исключены из Git. Видео также исключено из Git.
Исходный `tests/check.sh` не меняется; отпечаток — `06a02208c1f0`.
