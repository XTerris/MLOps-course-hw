# Четыре дефекта учёта экспериментов

Шуликов М. В. · ДЗ 6–7 · GitHub Issues.

Исходная заготовка сохранена коммитом `fb10999`. Тесты преподавателя не менялись; отпечаток всех файлов `tests/`: **c42ac7788026**.

## 1. Разные конфигурации записывались в общий run

`src/sweep.py` открывал один дочерний `all-candidates` на весь цикл. Параметры логировались только при первом вызове, метрики следующих адаптеров попадали в тот же run. Теперь цикл открывает отдельный вложенный run для каждой конфигурации. Проверки 1 и 3 сопоставляют шесть имён, параметры и число шагов.

## 2. Файлы терялись при замене контейнера

Postgres имел volume, но `/mlartifacts` оставался в файловой системе контейнера. В compose подключён именованный volume `artifacts:/mlartifacts`; метаданные и файлы сохраняются раздельно. `check-storage` записывает случайный probe, пересоздаёт только MLflow и сверяет SHA-256 скачанного файла. Это сильнее обычного restart.

## 3. Версии train/val отбрасывались

`provenance` вычислял SHA-256 обоих тензоров, но sweep исключал ключи `data_*`. Теперь все теги происхождения передаются родителю и каждому кандидату. Проверка 2 сверяет код, конфиг, данные, Git SHA и точную ревизию базы. Связь исходного train и токенизированных ID описана в `data-lineage.json`.

## 4. Регистрация обходила порог

Функция `gate` существовала, но `promote` напрямую вычислял отношение loss и изменял реестр. Теперь `gate(run, threshold)` вызывается до `register_model` и назначения alias: проверяются FINISHED, конечность метрик, положительный базовый loss и порог. Проверка 6 задаёт нулевой порог и ожидает отказ до регистрации.

## Два разных допуска

Loss-порог разрешает зарегистрировать `candidate`; он не назначает `champion`. Штатный `make promote` повторно пересчитывает оценку сохранённых ответов и проверяет качество. Неуспешная генерация, несовместимость протоколов и регрессия блокируют выпуск. Итоги фактической приёмки приведены в `conclusion.md` и журналах проверки.
